# PersonaLive 离线语音消息设计

## 目标

用户下载开源项目后，只需配置大模型等必要 Key 即可使用完整功能。语音识别使用本地 Qwen3-ASR 0.6B：首次自动下载模型，之后完全离线。用户发送语音，系统保存可播放音频，在后台转成文字并以文字调用现有 Agent，最终仍以文字回复。

## 范围

- 支持中文、英文、日语自动识别。
- 音频气泡可播放；转写默认折叠，可点击查看。
- 音频、转写和对话长期保留，刷新后恢复。
- 清空对话时同时删除音频、转写、对话记录和 LangGraph 检查点。
- 不包含说话人分离、时间轴、SRT、批处理、Gradio 或 Forced Aligner。

## 架构

Qwen3-ASR 运行在独立的本地 Worker 和隔离环境中，避免 PyTorch、Transformers 与 PersonaLive 主虚拟环境冲突。FastAPI 按需启动 Worker，通过仅绑定回环地址的本地接口发送音频。Worker 首次使用时自动下载官方 Apache-2.0 模型，并在推理后保持热加载。

不依赖 `D:\Qwen3_ASR` 才能运行正式项目；该目录只作为已验证参考。正式实现使用官方 `qwen-asr` 包和官方模型来源。

## 数据流

1. 浏览器结束录音并上传原始音频。
2. 后端先持久化音频和消息记录，状态为 `transcribing`。
3. 前端立即显示可播放气泡和识别进度。
4. Worker 自动识别语言并返回文字。
5. 后端保存转写，将其作为普通文本问题提交给现有 Agent。
6. 前端在音频气泡下提供折叠转写，并显示 Agent 的文字回复。
7. 失败时保留音频、标记 `failed` 并允许重试，不向 Agent 发送空内容。

## 存储

音频保存在 `data/audio/<conversation_id>/<message_id>.<ext>`。数据库新增持久化聊天消息，至少记录角色、消息类型、音频相对路径、转写、处理状态、错误和时间。音频读取接口支持浏览器播放与 Range 请求，并保持现有本机访问边界。

删除流程先锁定目标对话，再删除数据库消息与检查点，最后删除该对话音频目录；文件删除失败必须报告并可重试，不能静默留下隐私数据。

## 首次使用体验

设置页提供“本地 Qwen3-ASR”选项，不要求 API Key。首次语音输入显示模型下载进度；下载完成后自动继续当前转写。后续启动不联网。模型或 CUDA 不可用时显示明确原因和恢复操作，不自动回退到云端。

## 验收标准

- 中、英、日短语音可自动识别并触发文字回复。
- 音频在刷新和重启后仍可播放，转写默认折叠。
- 首次下载后断网仍可完成转写。
- ASR 失败不会调用 Agent，并可从原音频重试。
- 清空对话后对应数据库记录、检查点和音频文件全部消失。
- 未配置本地 ASR 时不影响现有文本聊天和其他功能。
