# PersonaLive 下载按钮与 API Key 显示设计

日期：2026-07-31

## 目标

修复应用内置 Embedding 切换后下载按钮仍不可用的问题，明确 ASR/TTS 已安装状态；允许用户在设置页随时切换 API Key 的隐藏与显示状态，并复制完整 Key。

## 已确认根因

- 当前 ASR 和 TTS 均已安装，前端按 `ready` 禁用下载按钮，但按钮仍显示“自动下载安装”，造成不可点击的误解。
- 当前 Embedding 使用云端通义配置并返回 `ready=true`；切换到应用内置模式时，下载按钮没有根据新模型重新计算，错误继承云端状态。
- `/api/settings` 只返回 `*_api_key_configured`，输入框保存后会清空，因此纯前端密码切换无法显示或复制已保存 Key。

## 下载按钮行为

- Embedding 切换 provider、模型或快捷预设后，按当前所选本地模型是否已安装重新计算按钮状态。
- 当前模型未安装：按钮显示“下载并启用”且可点击。
- 下载中：按钮显示“安装中”并禁用，同时显示取消按钮。
- 当前模型已安装：按钮显示“已安装”并禁用；选择其他模型后立即恢复可点击。
- ASR/TTS 已安装时下载按钮显示“已安装”并禁用；删除资源后恢复“自动下载安装”。
- 不增加隐式重新安装；需要重装时先使用现有删除操作，避免覆盖正在使用的资源。

## API Key 显示与复制

- 对话模型、云端 Embedding 和联网搜索的 API Key 输入框右侧增加眼睛按钮和复制按钮。
- 默认使用 `type=password`。
- 第一次点击眼睛或复制已保存 Key 时，调用受保护接口按需读取该字段明文。
- 眼睛按钮可随时在 `password` 与 `text` 之间切换，不设置自动隐藏计时器。
- 复制按钮复制输入框中的完整值，并通过设置页状态区域显示“已复制”。
- 用户输入的新 Key 不需要请求后端，可直接显示或复制。
- 应用保存设置后继续清空输入框；下一次显示时重新按需读取已保存值。

## 安全边界

- 普通 `GET /api/settings` 继续只返回是否配置，不返回任何密钥。
- 新增 `POST /api/settings/reveal-key`，请求体只允许 `openai_api_key`、`embedding_api_key`、`web_search_api_key` 三个固定字段。
- 接口复用 localhost、Host、Origin 检查，并额外要求 `X-PersonaLive-Request: web`。
- 响应禁止缓存；前端不写入 localStorage、sessionStorage 或 URL。
- 未配置字段返回空值；未知字段返回 422。

## 验证

- API 测试覆盖同源保护、字段白名单、已保存 Key 返回以及普通设置接口继续遮罩。
- 静态前端测试覆盖三组眼睛和复制按钮。
- JavaScript 测试或静态契约覆盖 provider/模型切换后下载按钮状态。
- 完整测试确认现有设置保存、ASR、TTS 和 Embedding 下载接口不回归。

## 验收标准

用户切换到应用内置 Embedding 后可以下载未安装模型；已安装的 ASR/TTS 明确显示“已安装”。用户可以通过眼睛按钮随时显示或隐藏三个 API Key，并通过复制按钮复制完整值，普通设置加载不会主动暴露密钥。
